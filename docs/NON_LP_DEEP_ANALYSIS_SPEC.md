# 非LP詳細分析規格

## 目的

LP以外の選定候補を、LP v2.2と同じく章番号が固定された詳細分析として蓄積する。
日次収集の全件を自動で詳細分析せず、週末レビューで選定した候補だけを対象にする。

規格名は drs-deep-1.0。本文は必ず第1章から第29章までを順番どおりに持つ。

## 対応媒体

| 種別 | ID | 主な分析対象 |
|---|---|---|
| バナー・Web広告 | BN-0001 | コピー、視線誘導、CTA、遷移先整合 |
| Webサイト | WB-0001 | FV、情報設計、PC/SP、問い合わせ導線 |
| Webアプリ・UI | UI-0001 | タスクフロー、状態、入力、フィードバック |
| グラフィック | GR-0001 | 文字組み、グリッド、写真、印刷・販促 |
| パーツ・Section | PT-0001 | 役割、構成要素、前後文脈、切り出し境界 |
| 原則・パターン | PAT-0001 | 定義、根拠、成立条件、失敗例、転用 |
| Canva参考 | CV-0001 | 差し替え容易性、情報階層、量産性 |
| 素材探索 | ASSET/PHAC/ILAC等 | 検索語、用途適合、作者、ライセンス |

媒体別の画像枠、分析Unit、重点項目、Notion推奨項目は
config/non-lp-deep-analysis-templates.json を正本とする。

1. 基本情報
2. 実画像・証拠

4. 詳細分析とパーツ管理の役割分担
5. エグゼクティブサマリー
6. 想定ターゲット・利用文脈・認知段階
7. 構成骨格・情報優先順位・視線誘導
8. 全Unit詳細分析
9. コピー・メッセージ・オファー・行動分析
10. 信頼形成・理解支援・反論処理
11. PC/SP・比率・媒体・状態差
12. 配色・タイポグラフィ・造形・素材配置
13. 良い点・弱い点・機会損失
14. P0/P1/P2改善案
15. 再利用価値のある候補
16. 権利・再利用ルール
17. 未確認・failure_reason・次工程
18. 媒体別参照プロファイル
19. 異業種・他媒体への転用例
20. ビジュアルトークン・制作条件
21. 提案時の抽出・評価ルール
22. 推奨データベース項目
23. 証拠・ファイル台帳
24. 更新・検証記録

27. 返却・後工程依頼文
28. 実行・重複防止記録
29. 更新履歴

## 第8章の固定形式

各媒体のUnitは次の12項目を必ず持つ。

1. 対象・位置
2. 役割
3. 観察できる内容
4. 構図・レイアウト
5. 情報階層・視線誘導
6. 配色・文字・素材
7. 媒体固有の評価
8. 目的・行動への寄与
9. 根拠
10. 再利用できる構造
11. 権利・除外要素
12. 確信度

見出しは「### Unit 01｜名称」の形式を変えない。

## 画像ルール

- バナーは対象バナーに加え、取得できる場合は遷移先PC/SPファーストビューを入れる。
- WebはPC/SPそれぞれのFull Page、First View、Section一覧の6枠を基本とする。
- UIは主要画面だけでなく、操作前・操作中・完了・エラーなど状態差を優先する。
- グラフィックは全体像に加え、文字組み、写真・図版、印刷・展開の拡大を用意する。
- パーツは対象画像と、元ページ内の位置、PC/SP差を用意する。
- Patternは根拠事例を原則2件以上とし、比較または反例を含める。
- Canvaはテンプレート全体、編集対象、別比率または展開例を記録する。
- 素材探索は素材自体を再配布せず、許可されたプレビューとメタ情報を証拠にする。
- 画像がない枠は古い画像で埋めず、failure_reasonを書く。

## 実行方法

1件のテンプレートを作る。

~~~bash
npm run analyze:non-lp:deep:template -- --id BN-0001
~~~

週末レビューで選んだ候補だけをまとめて作る。

~~~bash
cp data/non-lp-deep-analysis-selection.example.json data/non-lp-deep-analysis-selection.json
# selectedを実際の選定IDへ変更
npm run analyze:non-lp:selected:deep -- --selection data/non-lp-deep-analysis-selection.json
~~~

テンプレート構造を検査する。

~~~bash
npm run knowledge:validate-non-lp -- --input "<Markdown>" --mode template
~~~

画像確認と詳細分析を終えた完成版を検査する。

~~~bash
npm run knowledge:validate-non-lp -- --input "<Markdown>" --mode analysis
~~~

完成版では [要分析]、[要設定]、[要実測] を残さない。取得不能な項目は空欄にせず、
第17章と該当箇所に failure_reason、影響、代替情報、次の確認を記録する。

## 完了条件

- 第1章から第29章が重複なく順番どおりに存在する。
- 第8章の全Unitが12固定項目を持つ。
- 媒体別の固定画像枠に画像パスまたはfailure_reasonがある。
- 第15章と第26章の候補IDが一致する。
- URL、画像、寸法、状態などの根拠が第23章と第25章にある。
- 権利区分と除外対象が明記されている。
- Notionには媒体別の画像枠と29章本文を同じ順序で反映する。
- CBS同期候補JSONは詳細分析完了後に生成し、本番同期はユーザー確認後に行う。
