# Design Research Scout — 調査メニュー

実行ごとに走査対象を限定し、時系列で比較可能にするための調査範囲。エージェントは
メニューへの追加を**提案**できる（PRとして）が、無断で範囲を広げない。

指紋（検索修飾子・採用日算出パス）はコードで定義: `scripts/scout/fingerprints.mjs`。
このドキュメントは、その上に乗る「どの軸を測るか」という調査メニュー。

## 現在の指紋（最初の案・要見直し前提）

| 指紋 | 想定する意味 | 状態 |
|---|---|---|
| `tailwind.config.js` / `tailwind.config.ts` | Tailwind CSSによるユーティリティファースト設計の採用 | 初期案 |
| `design-tokens.json` | デザイントークン（色・タイポグラフィ等の構造化データ）の採用 | 初期案 |
| `figma.config.js` | Figma連携ツールチェーンの採用 | 初期案 |
| `.storybook`（ディレクトリ） | コンポーネント駆動デザインシステム（Storybook）の採用 | 初期案 |

**この指紋セットは暫定。** 実際に収集してみてノイズが多い・的外れだと分かった場合は、
指紋を入れ替える・増やすことを優先する（無理に今の指紋で結論を出さない）。

**既知の不確実性（2026-10-11、GitHub code searchで実クエリ確認済み）:**
`filename:figma.config.js`は完全一致ではなく、`figma.config.json`のような類似ファイル名も
結果に混ざって返ってくることを確認した。この指紋で件数を確定させる前に、実際の
検索結果を人が目視確認し、`.js`と`.json`を別の指紋として分けるか、クエリ自体を
見直す必要がある。`tailwind.config.js`・`.storybook/main`は実クエリで妥当な件数
（それぞれ約128万件・約2.9万件、2026-10-11時点）が返ることを確認済み。

## 測る価値のある軸

1. **採用時期の推移** — 指紋ファイルの最初のコミット日を四半期単位で見る。
2. **指紋間の共起** — 同じリポジトリが複数の指紋（Tailwind + Storybook等）を
   同時に持つか。
3. **指紋ごとの規模比較** — 各指紋のtotal_countの相対比較（directional floor前提）。
4. **（将来）デザインシステム成熟度の proxy** — 上記の組み合わせから、
   「デザインシステムをどこまで構造化しているか」の目安を作れないか検討する。

## 新規性ゲート（ドラフトを書くタイミング）

次をすべて満たす場合のみドラフトを書く。

- 既存の`knowledge/trends/`・`knowledge/ai-design/`や、`scan-log.md`で
  `drafted`/`rejected-thin`になっている候補でまだカバーされていない。
- コレクター（GitHub search + REST API）で測定可能。
- 1,000件キャップ＋重複除去後に n ≈ 250以上に届く。
- 自明でない（答えが既に常識ではない）。

どれも満たさない場合は、`scan-log.md`に観察結果だけ追記して安く終了する。
