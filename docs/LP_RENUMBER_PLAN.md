## 注意（先に決めたい点）
1. **旧 DIS 番号との衝突**: 新しい `DIS-LP-0004` は LP-0004 を指すが、旧 `DIS-LP-0004` は LP-0001 の分析を指す。同じ名前が、別のものを指す。Notion のページ名（`DIS-LP-0223｜…`）、台帳、Dropbox の `99_Needs_Review/.../DIS-LP-0229/` なども、旧番号を使っている。
2. **既存の ID を変える作業の範囲**: Notion（LP-nnnn のページ名）、CBS の参考事例（LP-0001〜0180、LP-0215 などの ID）、ナレッジ、台帳、Dropbox を、どこまで新番号にするか。**CLAUDE.md の約束は「既存のDropbox・Notion・CBS・ID・ナレッジ・分析を、上書き・移動・削除しない」**。変える場合は、ユーザーの明示的な指示と、手順の確認が必要。
3. **置き換えの方法**: その場で名前を変える（移動）と、元に戻せない。新しい名前で別の場所にコピーして、確認してから古い方を整理する方法が安全。
4. LP-0227・0228 は、案件別のフォルダがない（画像は `99_Needs_Review` にある）。新番号は振るが、画像の置き場は、別に決める。
5. アーカイブ画像（rdlp の全体画像）への揃え直し（`dis:archive-shots`）は、LP-0250 以降の番号で作っていたが、この計画と食い違う。**新番号に統一するなら、撮り直しの保存先の名前も、新番号にする。** 先の撮影（DIS-LP-0328）は、使わない。

## 決定（2026-11-21）
1. 旧 DIS 番号も、**新番号に振り直す**（Notion・台帳・Dropbox の `99_Needs_Review` などの旧番号は、別の段階で、手順とバックアップを確認してから行う）。旧→新の対応は、`data/lp-renumber-map.json` の `oldDisIds` に入っている。
2. Dropbox の置き換えは、**新しい場所（`10_LP_新番号`）にコピーして、確認してから**。元の `10_LP` は変更しない。

## コピーの実行ファイル（`dis:renumber-copy`）
```bash
git pull origin claude/stoic-davinci-b2ek8x
npm run dis:renumber-copy                      # ドライラン（件数・容量・名前の例・衝突の確認。何も書かない）
# 対応表を確認して、data/lp-renumber-map.json の "status" を "confirmed" にしたあと:
DIS_ENABLE_WRITES=true npm run dis:renumber-copy -- --apply
npm run dis:renumber-copy -- --verify          # コピー先と元の、ファイル数・容量を照合
```
- 既定の対象は、`01_案件別` と `02_セクション別`。参考用のフォルダ（91〜95）は、`--include 91_参考_概観図,…` で追加できる。
- 名前の中の `LP-nnnn`（旧LP番号）と `DIS-LP-nnnn`（旧DISの連番）を、`DIS-LP-mmmm`（新番号）に置き換える。旧DISの連番は、対応表の `oldDisIds` と、手元の `data/dis-relations.json`（Macには、GitHubより新しい分がある）から、LP番号を引く。
- 対応表にない `DIS-LP-nnnn`（撮影のときに、Dropbox の同期フォルダへ自動コピーされた分など）は、既定では止めて報告する。`--skip-unmapped` を付けると、除外して進める（元には残る）。重複のため除外した LP（LP-0135・0143）は、コピーしない（元に残る）。
- コピーは新規のみ。再実行は、容量が同じファイルをスキップ（途中から再開できる）。容量が違うものがあれば、上書きせず止まる。
- **容量**: コピーのぶん、Dropbox の容量とディスクを使う。ドライランに、コピーする容量（GB）が出る。
