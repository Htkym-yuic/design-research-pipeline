# 媒体別の分析項目表（案）

状態: **案（2026-11-11）。ユーザーの確認前。** まだコードにも `knowledge/` にも反映していない。確認後、各媒体3〜5件の手動の例で、項目が埋まるかを試してから、書式と検証を整える。

## 決定事項（2026-11-11）
- チラシ・ポスター・名刺は、ID は `GR` のまま、`graphicKind`（flyer／poster／businessCard）で区別する。
- **ロゴは保留。** 収集元が、既存の設定ではデザインAC（テンプレート）だけで、利用規約を確認していないため。収集元と利用規約が決まるまで、収集も分析もしない。表の項目は、再開のために残す。
- 収集元は、どの媒体でも、利用規約（自動取得・再利用の可否）を確認してから有効にする。デザインACも例外ではない。

## 前提（ユーザーの決定）
- ナレッジの用途: ①制作時の事例検索、②制作物の添削、③CBSの生成の根拠。
- 素材: 最終的に、画像を Dropbox に保存する。
- ロゴで学びたいこと: 業種ごとの傾向。
- 件数: まず、媒体ごとに1日1件ずつ。
- 媒体フォルダ名: `LP`／`バナー`／`Web`（英字に揃える案は、ユーザーが選ぶ）。

### 違いの要点
- **LP と Web の違い**: 構造の型（section_patterns）は共通。Web は、ナビ、会社情報、フッター、ページ種別（トップ、下層）が主で、CTA・価格・ファネルの項目は薄くなる。
- **LP・Web と B 段階の違い**: B 段階は、縦に長い全体画像とPC・SPの対応がない。その代わりに、1枚の中の視線の流れと、情報の主従が中心になる。
- **B 段階の 9軸**: LP・Web と同じ9軸の名前を使うが、軽めに評価する。根拠のない軸は書かず、確信度が低い軸は「未確認」にする。
- **C・D 段階**: 構造の分析はしない。検索（①）を中心にし、添削（②）の項目は、ロゴの「小さく表示した耐性」だけ。

### checks（添削用チェック項目）の書式
```
checks: [{ item, good, bad, severity, how }]
  item     : 確認する項目（例: 視線の起点が1つか）
  good     : 良い状態
  bad      : 悪い状態
  severity : 高／中／低
  how      : 確認の方法（例: 画像を縮小して、最初に目に入る要素を確認）
```
各事例から、2〜5項目を、根拠つきで抜き出す。事例ごとの「良い点」を、そのままチェックにしない（その事例の固有の事実と区別する）。

## 実装での注意
- ID の接頭辞: バナー `BN`、Web `WB`、グラフィック `GR`、パーツ `PT`、Canva `CV`、素材 `ILAC`／`PHAC`（既存のとおり）。チラシ・ポスター・名刺・ロゴは `GR` の中の `graphicKind` で区別する案。
- `knowledge/` の既存のディレクトリ（`banner`／`flyer`／`poster`／`business-card`／`logo`／`graphic`／`parts`／`asset`）を使う。`GR` の保存先を `graphic/` に一本化するか、種類別のディレクトリにするかは未決。
- 分析の検証（`validate-*`）は、媒体ごとに項目表から作る。バナーはすでに要素の一覧がある。
- 既存のナレッジ・ID・分析は、上書きも移動も削除もしない。
- デザインACのテンプレートは「事例」というより「素材」に近い。蓄えるときは、`quality` の区分（事例／素材）を付けて混ぜない。
- 外部への書き込み（Dropbox、Notion）は、既定で無効。
