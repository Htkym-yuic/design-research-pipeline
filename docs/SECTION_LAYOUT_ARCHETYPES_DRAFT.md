# Section の「型」（layoutArchetype）の一覧: 案 第2版

状態: **案（2026-11-12）。第1版への回答（下記）を反映済み。全体の最終確認は、ユーザーが行う。** CBS×DIS 統合の最初の一歩（`docs/CBS_DIS_INTEGRATION_REQUIREMENTS.md` の Q6・Q7・Q17）。

## 0. 第1版への回答（2026-11-12）
1. FV の型は、本文とは**別に持つ**（A 群の4種類）。
2. カードの列数は、**型を「cards」1つにして、列数（2／3／4+）を属性**で持つ。
3. 事例の少ない型（縦の時系列、文章中心、悩みチェックリスト、料金プランのカード、ナビ・フッター）も、**すべて含める**。
4. PC と SP で型が変わる場合は、**PC と SP で別々に型を持つ**（`layoutArchetype: { pc, sp }`）。

## 1. 目的
Section を「型」で分類する。CBS は型ごとのテンプレートで実装（DOM/CSS）を生成する。事例の画像は使わず、構造だけを使う。

## 2. 「種類（roleType）」との違い
| | roleType（今ある） | layoutArchetype（これから） |
|---|---|---|
| 問い | その Section は、何のためにあるか | その Section は、どんな形をしているか |
| 例 | FV／悩み提起／料金／FAQ／CTA | 左右分割／カード3列／番号付きリスト |
| 数 | 約17種類 | 約20種類（案） |
| 関係 | 1つの roleType が複数の型を取りうる（「特徴」→ カード3列／番号付き／左右交互） | 1つの型が複数の roleType で使われる（カード3列 → 特徴・実績・料金） |

構成案の生成では、roleType で並びを決め、型で見た目を決める。

## 3. 調べた範囲
- CBS: 181件の参考事例、**Section 1,404件**（`sectionBreakdown`）。
- DIS: LP の Section **127件**（`knowledge/lp/*.json` の `section_patterns`）。
- CBS 側には、型の項目がない。文章（カード・表・FAQ、画像・人物・商品配置、PC/SP 差、装飾）に、レイアウトの言葉が散らばっている。
- 下の「該当数」は、それらの文章に、レイアウトの言葉が出てくる Section の数。**分類の結果ではなく、目安**（1つの Section が複数に重なる）。型の付与は、確定後に行う。

## 4b. 属性（型に付ける）
| 属性 | 値 | 付ける型 |
|---|---|---|
| columns | 2／3／4+ | cards（B2）、pricing-cards（D2） |
| modifiers | 縦書き／斜めの区切り／アイコン列／帯背景 | すべての型 |
| device | pc／sp | 型は、デバイスごとに持つ（下の書式） |

### 型の書式（案）
```
layoutArchetype: {
  pc: { type: "cards", columns: 3, modifiers: [] },
  sp: { type: "cards", columns: 1, modifiers: [] }   // SP で1列に縦積み
}
```
- PC と SP は、別々に型を付ける。片方しか画像がない事例は、ない方を省略する。
- 型の合計は、**24種類**（A 4種類、B 8種類（cards は1つに統合）→ 実質 B 7種類、C 5種類、D 6種類）。
